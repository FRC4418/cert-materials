## Required behavior (all must pass)
- [ ] Repo cloned and opened; commit includes a purposeful change only.
- [ ] Git status/diff and remote push demonstrate a clean reviewable contribution.
- [ ] No generated artifacts, credentials, or unapproved production edits are included.
- [ ] Student can explain clone, commit, pull, push, and branch at a basic level.

## Reproducible evidence
1. Clone an authorized training repository or approved branch, never the competition robot production branch unless granted permission. Show where files appear locally.
2. Make a small meaningful change: improve a comment, adjust a test constant within allowed bounds, or add a short README note. Run WPILib build if source code changed.
3. Use git status and git diff, then stage only intended files, commit with a descriptive message and push to an authorized branch; the proctor verifies the changed file online.
4. Student explains the difference between local commit and remote push, and identifies which files should not be committed (e.g., build/ artifacts). Merging, resolving conflicts and PR approvals are left to later tiers.

## Safety / test policy
- This is a beginner FRC programming assessment. No simulation or advanced control is required.
- If a physical motor is involved, an authorized proctor controls the enable/disable process, checks current limits and secures the test bench.
- No production robot deployment, unapproved wiring, or bypass of safety interlocks.
- Any `ProctorTest.java` file is protected and must remain unchanged.
