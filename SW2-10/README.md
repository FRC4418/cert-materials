# SW2-10 — Basic Git and Sharing Robot Code

## Prerequisites
- SW2-00 through SW2-09.

## Goal
Make one safe, reviewable contribution to training robot code using basic Git workflow.

## Student files
- This task uses a fresh WPILib-generated project; no prewritten Java solution is provided.

**Student may edit** the starter files and the generated WPILib project, but must NOT edit any ProctorTest.java or PROCTOR_RUBRIC.md. Reuse the completed files from previous SW2 assessments when stated; do not copy a proctor's solution. 

## Procedure
1. Clone an authorized training repository or approved branch, never the competition robot production branch unless granted permission. Show where files appear locally.
2. Make a small meaningful change: improve a comment, adjust a test constant within allowed bounds, or add a short README note. Run WPILib build if source code changed.
3. Use git status and git diff, then stage only intended files, commit with a descriptive message and push to an authorized branch; the proctor verifies the changed file online.
4. Student explains the difference between local commit and remote push, and identifies which files should not be committed (e.g., build/ artifacts). Merging, resolving conflicts and PR approvals are left to later tiers.

## Preparation
Git official documentation: git clone, status, diff, add, commit, push; WPILib project file structure.

Do not enable or deploy live motor code until the proctor verifies safety.
